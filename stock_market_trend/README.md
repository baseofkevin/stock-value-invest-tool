# stock_market_trend — A股大势粗判：趋势 / 赔率 / 情绪

把沪深300 的**周线趋势**、**ERP 赔率分位**、**破净率 + 周换手量能**三路信号各算一遍，
原件落 `shared.db`、结论落 `results.db.market_regime`（一周一行）。

三路**各算各的，不合成总分、不给买卖结论**——产出的是一块背景板，回答"现在大概在
什么位置"，拍板仍然由人做。

```bash
python3 -m stock_market_trend                              # 基准日 = 今天
python3 -m stock_market_trend --date 2026-11-20            # 给指定基准日
python3 -m stock_market_trend --date 2026-06-22 --recompute # 不联网，用库里的原件重算
python3 -m stock_market_trend --json /tmp/trend.json       # 另存一份 JSON
python3 -m stock_market_trend --quiet                      # 不打印 4 行抓取进度
```

日常用 `./run.py trend`（多一层交易日历校验和日志），或直接 `./run.py all`
（它是全流程的第 ⑤ 步）。

## 为什么单独一个包

它和 `stock_data_fetch` 没有代码依赖，只共用**文件路径约定**（同一个仓库根、
同一组环境变量名 `STOCK_SHARED_DB` / `STOCK_RESULTS_DB`）：

- 四个上游接口（五次抓取）、四张 raw 表、三套阈值全在本包里，数据层不需要为它升一次
  `SCHEMA_VERSION`；
- `market_regime` 由本包自己 `create table if not exists` 建，**不跑本包就永远不存在**，
  老库零影响；
- 它是**背景板**，四个工具（选股/周期/质量/顶部）的结论一个字都不读它。
  所以 `run.py all` 里它排最后，而且**算不成也不拦主流程**。

## 设计立场：三路不合并

"趋势空头但估值便宜"是合法状态。合成一个总分只会把它抹平：2026-11 现在就是
"趋势空头确认 + ERP 85% 分位（便宜）+ 破净率 96% 分位（恐慌）"，压成一个
"中性偏谨慎"等于把这三句话全丢了。

原文（那份分享对话）里有四个词写不进程序——"收不回""拐头""向下发散""放量长阳"。
这里全部换成可复现的算术，且只保留最少的几条：

| 原话 | 这里的算法 |
|---|---|
| 收不回 MA20 | 连续 2 周收盘 < MA20（`CONFIRM_WEEKS = 2`） |
| 均线拐头向下 | MA20 < MA60 且 MA60 低于 4 周前（`SLOW_SLOPE_WEEKS = 4`） |
| 估值贵/便宜 | ERP 在近 10 年的**分位**，不看绝对值 |
| 放量长阳 | 周换手率 ≥ 近 52 周中位数 × 1.5（天量线） |

阈值全部用**分位**或**相对水位**，不用固定数字：固定数字过上几年必然失效
（1.0%~1.5% 的换手率地量线就是 2014-2019 的化石）。

## 数据流向

```text
上游（5 次抓取 / 4 个接口）
  ① 东财 push2his 周K        ┐
  ② 中证 index-perf 日频 PE  ├─ shared.db（原件层）  四张表，只存上游原值
  ③ 东财 10 年国债           │
  ④ 乐咕 全A破净统计         │
  ⑤ 东财 push2his 日K        ┘   ← 只喂看板日线视图，不进判定
                                └─ rules.judge()  ← 纯函数，不碰网络不碰库
                                     └─ results.db.market_regime（结果层，一次运行一行）
                                          └─ 看板 /trend（历史表）与 /batches（横幅）
```

**原件层不算派生。** 没有 MA、没有分位、没有任何派生列——一旦在原件层算派生，
改阈值时就不知道该信哪一层。派生只出现在结果层，所以改阈值可以 `--recompute`
重算，不必重新下载；上游挂了也能拿上一次的原件出周报。

| 库 | 表 | 粒度 | 内容 |
|---|---|---|---|
| `shared.db` | `market_index_week` | 一周一行 | 沪深300 周K + **周换手率**（`turnover`） |
| `shared.db` | `market_index_day` | 一天一行 | 沪深300 日K + **日换手率**（只给看板画日线） |
| `shared.db` | `market_index_perf` | 一天一行 | 中证官方 收盘 + 滚动PE（`pe_ttm`）+ 样本数 |
| `shared.db` | `market_macro` | 一天一行 | `series` = `bond10y` / `below_na` |
| `results.db` | `market_regime` | 一次运行一行 | 三路的状态、分位、四条线快照 + 整份 `payload` |

前三表的 `symbol` 固定写 `sh000300`；`market_macro` 用 `series` 区分两条宏观序列，
破净那一路的 `extra` 列存 `{"below":n,"total":m}`（JSON 字符串）。

四张 raw 表的写入方式是**按主键 upsert**，不是 `DELETE WHERE date` 整天替换
（`price` 表是那么做的）。理由：`price` 一天一份全市场快照，"这天有哪些票"本身是
原子事实；而这里四张表是**序列**，每次抓的全是历史区间，按主键 upsert 就够了，
也就不会因为上游少回几行把历史挖出个洞。

**唯一的例外是周K 的半根 bar**：周中跑会给一根"当周至今"的日期的临时周线，
下一次周五跑，完整周落在**新日期**上，upsert 顶不掉它，那根假的 1 天周线会永久
留在序列中间（图上多一个坑、MA 窗口挪位、52 周中位数被拉低）。所以 `save_week()`
写完之后会调 `_drop_older_in_week()`，把最新一根所在 ISO 周里更早的行清掉。

写 raw 的同时顺手登记 `watermark`（`domain='market'`，`scope` = `index_week` /
`index_day` / `index_perf` / `bond10y` / `below_na`），这样 `stock_data_fetch` 的
`doctor` 免费获得一份新鲜度体检，不必另写一套。

## 四个上游与各自的坑

| 源 | 接口 | 为什么用它 | 必须知道的边界 |
|---|---|---|---|
| 沪深300 周K | 东财 `push2his`（`klt=102`，`fqt=0`） | 一次给 11 年周线，**`f61` 就是周换手率**；中证官方不给换手率，而"地量"只能靠换手率判（成交额会被点位高低带偏） | 当周那根**实时更新**：周五盘后是完整周，周中是半周 |
| 日频 PE | 中证 `index-perf` | 官方估值，一次 970KB 给 2015 至今日频收盘 + 滚动PE，`peg` 字段零空值；与收盘同源，趋势和估值口径自洽 | **滞后一到两个交易日**（2026-11-20 实测：东财已有 11-20 收盘，中证最新 11-19），所以有 `data_asof` |
| 10 年国债 | 东财 `RPTA_WEB_TREASURYYIELD` | 一张表里塞了中美各期限，`EMM00166466` 是中国的 10 年；`filter` 卡到 2015，约 7 页取完 | 只取 `BOND_START = 2015-01-01` 之后——ERP 分位窗口就是 10 年，更早的用不上 |
| 全A破净 | 乐咕 `below-net-asset-statistics-data` | 一次性返回 2005 至今的破净家数/总数，不用自己攒 | 用的是页面上的**固定 token**（与 akshare 里那个一样），它变了就 403；这一路挂了不影响趋势和估值 |

`source.py` 里所有数值都过一道 `_f()`：上游可能给字符串、`"-"`、`None`，一律退化成
`None` 而不是猜一个 0。`_get()` 的 `RETRY = 2` 只重试**网络层**异常，4xx 直接抛
（"问错了"重试不会变对）；UA 是必须的，默认的 `Python-urllib/3.13` 在乐咕上直接 403。

## 三路判定

三路都是纯函数（`list[dict]` 进 → `dict` 出），都收一个 `as_of`。

### 1. 趋势（`rules.trend`）

输入：`market_index_week` 的周线（date / close）。

- **至少要 64 根周线**（`MA_SLOW 60 + SLOW_SLOPE_WEEKS 4`），不够返回 `None`；
- 两个条件各自算 0/1 分：

| 条件 | 判据 | 代码 |
|---|---|---|
| 收在 MA20 下方 **连续 2 周** | `close[i] < ma20[i]` 且 `close[i-1] < ma20[i-1]` | `below20` |
| 均线空头排列且 MA60 下行 | `ma20[i] < ma60[i]` 且 `ma60[i] < ma60[i-4]` | `bear` |

然后：

| `score` | 状态 | 说明 |
|---|---|---|
| 2 | **空头确认** | 两条同时成立 |
| 1 | **偏弱** | 只有一条成立 |
| 0 且 `ma20 > ma60` 且 `close > ma20` | **偏强** | |
| 其余 | **中性** | |

`score == 0` 但均线还没多头排列（或收盘在 MA20 下方一天）→ 中性，不给"偏强"。

输出字段：`state` / `score` / `date` / `close` / `ma20` / `ma60` /
`ma60_slope`（= `(ma60[i]/ma60[i-4]-1)*100`，带符号百分数）/
`weeks_below_ma20` / `weeks_below_ma60`（都是**连续**周数，从最新往前数，
遇到不满足就断）。

> `weeks_below_ma60` 只进 `payload`，**表里没有这一列**（见"表结构"）。

### 2. 赔率（`rules.valuation`）

```
ERP = 100 / PE(TTM) − 10年国债收益率(%)
```

- 按日期把国债收益率贴到每个交易日上：国债只到 T-1 时**沿用前值**（周五那天的 ERP
  用的就是当天已公布的最新收益率）；PE 日期早于最早国债日期的记录直接跳过；
- 窗口 = 最近 `ERP_WIN = 2400` 个交易日（约 10 年）；
- 分位 = 窗口内**严格小于**当日 ERP 的占比，`round(..., 0)` 取整到 0~100。

| 分位 | 状态 |
|---|---|
| ≥ 95（`ERP_EXTREME`） | **极值** |
| ≥ 80（`ERP_CHEAP`） | **便宜** |
| ≤ 20（`ERP_EXPENSIVE`） | **偏贵** |
| 其余 | **中性** |

输出还带 `mean`（窗口均值）和 `n`（窗口实际条数，满窗就是 2400）。

用**分位**不用 σ：ERP 分布厚尾，σ 和分位对不上。

### 3. 情绪（`rules.sentiment`）

两件事各判各的：破净率给"情绪状态"，周换手率给"量能档位"。

**破净率**（`below_na`，全A破净家数 / 总数 × 100）：

| 近 `NA_WIN = 2400` 日分位 | 状态 |
|---|---|
| ≥ 90（`NA_PANIC`） | **恐慌** |
| ≥ 70（`NA_COLD`） | **偏冷** |
| 其余 | **正常** |

分位高 = 破净多 = 恐慌，方向与 ERP 相反，别记混。

**量能五档**（周换手率，%）：判定顺序是「先地量（绝对地板压过一切）→ 再天量 →
最后在中间三档里走」。

| 档位 | 判据 |
|---|---|
| **地量** | `turnover ≤ 1.0`（`TURNOVER_DRY`，固定绝对值） |
| **天量** | `turnover ≥ 天量线` |
| **缩量** | `turnover < 缩量线` |
| **放量** | `turnover ≥ 放量线` |
| **平稳** | 其余 |

注意 `volume_lines()` 返回 `None`（窗口不足半年）时退化成"只判地量，其余一律正常"，
不硬造剩下四档。而 `sentiment()` 只在**完整周线 ≥ 60 根**时才调它——所以实际
不会走到这条退化路（60 根里至少有 52 根可做窗口）。

`turnover` 为 `None` 时返回 `None`（页面显示 `—`）；**有换手率但还没算出线**时返回
`"正常"` 而不是 `None` ——后者会让页面说"没数据"，而它其实只是"没有线可依"。

### 量能四条线：全部从同一个水位派生

```text
M      = 近 52 周（TURNOVER_HEAVY_WIN）周换手率中位数     ← 唯一的基准水位
地量线 = 1.0                                      （绝对值，不参与派生）
缩量线 = floor(M × 0.9 × 10 + ε) / 10，再被地量线兜住 max(1.0, …)
放量线 = ceil(M × 1.1 × 10 − ε) / 10
天量线 = ceil(M × 1.5 × 2 − ε) / 2                （向上取整到 0.5%）
```

**为什么地量线是固定的、其余三条是相对的？** 换手率下端有结构性地板（ETF 申赎、
量化、指数调仓的刚性成交），缩不下去——近十年 10% 分位一直只在 0.96%~1.41%
之间打转，钉在 1% 等于钉在分位上，十年没偏过。而**上端没有盖子**：2015 年能到
8.67%，2023 年最高才 3% 出头，中间三倍差距全看当年有没有情绪事件。写死一个天量线
必然两头落空：4% 在 2016-2023 有六年一次没触发，2026 年却触发了三成——"天量"
被用成了"常态"。改成跟着近一年的常态水位走，市场抬到 3% 它自己变 4.5%，
回落到 1.5% 它自己变 2.5%，不需要人校准。

**取整方向不是随手定的**：界值都是闭区间，上限向上取整、下限向下取整，让「平稳」
这一档尽量宽、两头的标签宁缺勿滥。`_EPS = 1e-9` 是抵浮点噪声的——`2.0×1.1×10`
在二进制里是 `22.000000000000004`，直接 `ceil` 会得到 2.3 而不是 2.2。

**「缩量」会被「地量」吃掉**：缩量线已被 `max(TURNOVER_DRY, …)` 兜住，市场整体
缩到 1.1% 上下时缩量线就贴到 1.0%，此时"缩量"这一档没有空间——这不是漏判，
是整个市场都蹲在地板上，"比平常再缩一点"没有增量信息。

库里 2026-11-23 那行的真实读数（可直接对照）：

```text
median52 = 3.01  →  缩量线 2.7 · 放量线 3.4 · 天量线 5.0
当周（上一完整周 2026-11-20）换手 2.70  →  2.70 不小于 2.7、也够不到 3.4  →  平稳
```

`turnover_pct`（近 `TURNOVER_WIN = 260` 周分位）**只当参考值**，不参与分档——
它回答"这周在近 5 年里排第几"，不回答"量够不够"。同理 `turnover_q10` / `q90` /
`q95` 也只是参考，图上不画。

### 基准日（`as_of`）在哪落地

三个函数进来第一件事都是 `_cut(series, as_of)`：只留 `date <= as_of` 的记录，
再照原样算。日期是 ISO 字符串，字典序即时间序，不用解析成 `datetime`。

所以"回填 6 月那一周"和"跑本周"走的是**同一段代码**，没有另写一条历史分支：

```bash
python3 -m stock_market_trend --date 2026-06-22
#   → 趋势用 06-18 那根周线（06-19 端午休市，那一周没有周五）
#   → 估值用 06-22 当天的 PE 与国债
#   → 情绪用 06-22 的破净率 + 06-18 那根完整周线
#   → data_asof = min(06-18, 06-22, 06-22) = 2026-06-18
```

`as_of=None` = 取序列最后一项（老行为）。

### 周中那根"半根 bar"：`split_partial()`

东财周K 在周中会返回一根**当周至今**的 bar（日期 = 最新交易日）。它的 `close` 是
当天收盘（当价格看没问题），但 `volume` / `turnover` 只累计了几天。2026-11-23（周一）
那根只有上周的 23% 成交量、换手 0.61%——拿它去比"周"的四条线，会凭空判出一个「地量」。

判据（`rules.split_partial`）：

```text
这根 bar 的日期 ≤ today
且 与 today 落在同一个 ISO 周
且 today 的 weekday() < 4        # 周一~周四；周五盘后跑它就是完整周
→ 判为"本周未走完"，从序列里摘掉，返回 (weeks[:-1], {date, turnover, close, prev_date})
```

- 摘掉之后**档位按上一完整周判**，`prev_date` 就是那一周的日期；
- 跨周之后它自然变成完整周，不需要人工标记，也不查交易日历；
- **只有情绪这一路摘**。趋势那一路不摘（见"已知边界"第 1 条）。
- 代价：节假日前最后一个交易日（周三/周四）当天跑，会被保守判成"未走完"，
  退回上一周——那一天的档位晚一周生效，但不会错判。宁可说"没走完"。

### 隔两三周才跑一次：原件连续，结论采样

这个包**不是每日任务**，实际节奏可能是 1 周、也可能是 2~3 周跑一次。
两层的处理方式不一样，别混：

| | 数据来源 | 跑得稀会怎样 |
|---|---|---|
| `/trend` 那张图 | `market_index_week` / `market_index_day` 原件 | **不受影响**。东财一次给全历史，跑一次就把中间漏掉的周/日全部 upsert 进来，图上右端一次长好几根，一天不缺 |
| `market_regime` 表 | 每次运行的结论 | **就是采样**。一次运行一行，隔三周跑中间那两周没有行，这是设计如此 |

所以不要把表当成"周序列"用——它记的是"我当时怎么判的"，缺的那几周本来就没人判过。
图上那些周照样有价有量，因为图读的是原件。要看完整序列看上面那张图。

日K（`hs300_day`）就是为了"跑得稀也能看日线"才加的：周K 一周只有一根、周中还只是半根，
中间的日子只有日K 才有。它**不参与任何判定**——趋势的 MA20/MA60 是"周"语义，
量能四线是"近 52 周中位数"派生的，换日频等于把整套阈值推翻重来。看板把它画成
独立的"日线"视图，口径另算（近 252 个交易日、地量 0.2%），并在页面上写明不参与档位判定。

日K 抓取失败**不进 `stale`**：它只影响日线视图的新鲜度，三路结论一个字都不会变，
把它算进去会让页面横幅谎报"部分数据沿用上次"。

## 降级与失败语义

这是原件层存在的意义：**不让一个 403 把整份周报拖没**。

先分清「五个抓取」和「三路结论」——它们不是一一对应的：

| 抓取（5 个，有进度行） | 喂给哪一路结论 |
|---|---|
| ① 沪深300 周K | **趋势 + 情绪**（量能档位要周换手率） |
| ② 沪深300 滚动PE | 赔率（分子） |
| ③ 10 年国债 | 赔率（分母） |
| ④ 全A破净率 | 情绪（情绪状态） |
| ⑤ 沪深300 日K | **不喂任何结论**，只给看板画日线视图 |

所以周K 那一路挂了，是"趋势 + 量能档位"一起受影响；破净率挂了只影响"情绪状态"，
量能档位照常。

每一路都是 `抓取 → 写原件 → 返回`，`except Exception` 兜住任何异常后**退回库里
上一次成功的原件**，并给这一路打 `stale` 标记：

| 情况 | `stale` | 结果 |
|---|---|---|
| 四路全部抓取成功 | 0 | 正常 |
| 某一路抓取失败、库里**有**原件 | **1** | 用旧原件照常出结论，页面横幅写"⚠️ 有源沿用上次" |
| 某一路抓取失败、库里**也空** | 0 | 这一路留空。若缺的是国债/PE → 赔率整路 `None`；缺的是周K → 趋势 `None` 且量能档位全空；缺的是破净 → 情绪状态空、量能照常 |
| 三路结论全空 | — | **不写库**，`stderr` 报警，退出码 **2** |

```text
[trend] 全A破净率 抓取失败（HTTP Error 403: Forbidden），改用 shared.db 上次的原件
```

`stale = any(s1, s2, s3, s4)`。注意判定条件是 `bool(rows) and not recompute`：
`--recompute` 本来就不联网，读库是它的正常工作方式，不算降级。

**第 ⑤ 路（日K）不在 `stale` 里**。它不喂任何结论，挂了最多让看板的日线视图停在
旧数据上，三路判断一个字都不会变；算进去只会让页面横幅谎报"部分数据沿用上次"。
它的失败只在 stderr 留一行，退出码不受影响。

三路全空时的告警会顺手报出最早的原件日期，方便判断是"库是空的"还是"基准日太早"：

```text
[trend] 三路都没算出来，不写库（基准日 2026-11-20；最早的原件是 2015-03-06）
```

## 表结构

### `results.db.market_regime`（21 列，`date` 为主键）

| 列 | 来源 | 说明 |
|---|---|---|
| `date` | CLI `--date` | **基准日**（不是数据日） |
| `computed_at` | 运行时刻 | `datetime.now()` 到秒 |
| `data_asof` | 三路 `date` 的**最小值** | 页面上的"数据截至" |
| `stale` | 降级标记 | 0/1 |
| `trend_state` / `trend_score` | 趋势 | 状态 / 0~2 分 |
| `trend_close` / `ma20` / `ma60` / `ma60_slope` | 趋势 | 收盘与均线快照 |
| `weeks_below_ma20` | 趋势 | 连续周数 |
| `erp` / `pe_ttm` / `bond10y` / `erp_pct` | 赔率 | ERP / PE / 国债 / 分位 |
| `below_na` / `below_na_pct` | 情绪 | 破净率 / 分位 |
| `turnover` / `turnover_q10` | 情绪 | 当周（上一完整周）换手 / 近 5 年 10% 分位 |
| `volume_dry` | 情绪 | 1 = 地量（旧字段，跟着 `volume_state` 走） |
| `payload` | — | 整份 JSON，以后加字段不改表 |

**只在 `payload` 里、不进表的字段**（改表要迁移，而这些是"说法"不是"事实"）：

`weeks_below_ma60`、`valuation.mean` / `n`、`sentiment.turnover_pct` /
`turnover_q90` / `q95` / `low_line` / `high_line` / `heavy_line` / `median52` /
`volume_state` / `partial_week`、`summary`、`below_count` / `total_count`。

`volume_dry` 之所以是旧字段还留着：看板与 payload 里都有人读它，让它**跟着分档走**
（`bool(volume_state == "地量")`），免得同一个换手率在"地量"和"未地量"之间出现两套说法。

### 一周一行，不是一次一行

同一个周五重跑三次，应该覆盖成"我最后看到的那一份"——所以 `save()` 用的是
`insert or replace`，按 `date` 覆盖。看板读的是"每个基准日当时的判断"，
跟 `run` 表按次记录的语义**不一样**。

### `shared.db` 四张 raw 表

```sql
market_index_week(symbol, date, open, high, low, close, volume, amount,
                  turnover, pct_chg, src, updated_at)   -- PK(symbol,date) WITHOUT ROWID
market_index_day (symbol, date, open, high, low, close, volume, amount,
                  turnover, pct_chg, src, updated_at)   -- 同上，日频
market_index_perf(symbol, date, close, pe_ttm, sample_size, src, updated_at)
market_macro(series, date, value, extra, src, updated_at)
```

四张表都 `WITHOUT ROWID`（主键就是全部索引，省一次 B 树）。`src` 记
`eastmoney` / `csindex` / `legulegu`，`updated_at` 是写入时刻。

## CLI 全参数

| 参数 | 默认 | 含义 |
|---|---|---|
| `--date YYYY-MM-DD` | `date.today()` | **基准日**，不只是标签：三路都按 `date <= 基准日` 截断后再算 |
| `--recompute` | 关 | 不联网，直接用 `shared.db` 里的原件重算（改阈值后用）。**不打印抓取进度** |
| `--json PATH` | 无 | 另存一份 `{"date","stale","trend","valuation","sentiment","data_asof","summary"}` |
| `--quiet` | 关 | 不打印 5 行抓取进度、不打印摘要前的空行、不回显 JSON 路径。**摘要仍然打印** |

| 退出码 | 含义 |
|---|---|
| 0 | 结论已写入 `market_regime`（哪怕 `stale=1`） |
| 2 | 三路全空、**没写库**；参数错误时 argparse 也退 2（两种含义共用，靠 stderr 区分） |

没有退出码 1：这个包没有"部分失败"这种状态——某一路失败会降级，不会中断。

进度行是给 `run.py` 的进度条认的格式（`[n/m]` 开头），独立运行时它就是个序号：

```text

[2/5] 沪深300 滚动PE
[3/5] 10年国债
[4/5] 全A破净率
[5/5] 沪深300 日K（看板日线视图）
```

## 与 `run.py` / 看板的接口

```text
./run.py all                 全流程第 ⑤ 步（最后一步）；失败只打一行警告，不拦主流程
./run.py trend               单跑；先过交易日历校验（pick_date），再把 --date 传进来
./run.py trend --date …      透传
./run.py trend --recompute   透传
./run.py all --skip-trend    跳过
./run.py all --trend-args "--recompute"   透传给本包
```

`run.py` 传进来的 `--date` 是 `pick_date()` 定下的**目标交易日**（通常是周五，
但节假日会是那周最后一个交易日如周三/周四），不是"今天"。它**不套** `tool=` /
`day=` 那套计数——那两个参数是给四个工具数"成功几只"用的，本包的产出不在
`*_result` 表里。

看板两处读它：

| 页面 | 读什么 | 说明 |
|---|---|---|
| `/batches`（首页）顶部横幅 | `db.regime(conn)` 默认 `limit=8` | 只摆最近 8 周 |
| `/trend`（A股大势） | `db.regime(conn, limit=None, start=, end=)` | 全量历史表，`start`/`end` 是**闭区间**、按**基准日**过滤 |

看板**不重算任何东西**：分位、状态都是本包跑完就定格的。`/trend` 那张量能图上的
三条折线是例外——它们要 260 根周线，`market_regime` 一周只有一行凑不出来，所以
`web/db.py` 破例只读 `shared.db.market_index_week`，取法与 `rules.volume_lines()`
**逐字一致**（`tests/test_web.py` 有一条断言把两边的常量与算法钉在一起，改一边
不改另一边会挂测试）。

## 已知边界（现状，不改代码）

1. **趋势那一路不摘"未走完的半根"。** 只有 `sentiment()` 调 `split_partial()`，
   `trend()` 直接把 `market_regime.payload.trend.date` 记成当周那天、`close` 记成
   当天价。所以**这个包只该盘后跑**（`run.py` 的 15:05 收盘宽限就是为这类判定
   设的）。周中跑不会错得离谱（价格是真的），但那根 bar 还不是周收盘价。
2. **节假日前最后一个交易日当天跑**，会被保守判成"未走完"，量能档位晚一周生效。
   不会错判，只是慢一拍。
3. **`below_count` / `total_count` 在 `--recompute` 与降级路径下恒为 `null`。**
   `store_raw.read_macro()` 只 `select date, value, extra`，`extra` 里的
   `{"below":n,"total":m}` 没有被解析回 `below` / `total` 两个键，而
   `sentiment()` 读的是 `last.get("below")` / `last.get("total")`。联网抓取那一路
   （`source.below_na()` 直接产出 `below` / `total`）是对的。
4. **`--date` 不做日历校验。** `main()` 里没有读交易日历，传 `--date 2026-06-21`
   （周日）也会照常按字符串截断算出一个基准日为周日的行。走 `./run.py trend`
   会先过 `pick_date()`（非交易日直接退 4），绕过 `run.py` 就是裸奔。
5. **`shared.db` 若是本包首次创建的全新库**，`watermark` 表不存在，
   `_watermark()` 会抛 `no such table: watermark`，被 `_fetch_or_fallback` 当成
   "抓取失败"，日志里会出现一句误导性的"抓取失败"。规避：让数据层先跑一次
   （`shared.db` 的 `watermark` 由 `stock_data_fetch/schema.sql` 建）。
6. **`market_regime` 按 `date` 覆盖**。同一基准日重跑会盖掉上一份，不回滚、不留痕。
   想看"那天我第一次跑出来是什么样"，只能靠备份。
7. **改阈值只影响之后重算的行。** 历史行是定格快照，`--recompute` 也要逐个基准日
   重跑才会更新，不会自动回填整段历史。

## 术语速查

| 词 | 含义 |
|---|---|
| 基准日（`as_of`） | 这次判断"站在哪一天"。存进 `market_regime.date` |
| `data_asof` | 三路里**最旧**的那一天的日期。中证慢一天，所以常比基准日早 |
| `stale` | 有源降级到上次原件 |
| ERP | 盈利收益率 − 10 年国债 = `100/PE(TTM) − bond10y`，单位 % |
| 分位 | 窗口内**严格小于**当值的占比（0~100 的整数） |
| 完整周 | 走完的周线。周中那根半根 bar 不算 |
| 地量 | 周换手 ≤ 1.0%（绝对值） |
| 缩量线 / 放量线 / 天量线 | 近 52 周中位数 × 0.9 / 1.1 / 1.5，逐周不同 |
