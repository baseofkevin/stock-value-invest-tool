# 综合评估：三条硬门槛说明

> **命名**：2026-11-20 起，页面上这块叫「超级成长股标识」，表格那一列也从
> 「门槛」改成了「超级成长股标识」。**代码和本文仍叫"硬门槛"/`gates`**——
> 改的是给人看的名字，不是规则。

日期：2026-11-20　范围：`stock_review/`（新增）、`web/`、`tests/`
验证：`python3 -m unittest discover -s tests -t .` → **175 通过**；`/review` 200。

**一句话**：三条门槛（不亏损 / 增速 / 供需）只做**标识**，不排除、不分档、
不排序；判定只用数据库里现成的数，不引入任何手写备注。

## 一、代码结构

```
stock_review/            ← 2026-11-20 从 web/review.py 搬出来，与 stock_kline_screen 平级
    config.py            全部阈值（赔率分 + 门槛），一处集中
    gates.py             三条门槛，纯函数：吃 fin 字典，吐 pass/fail/unknown
    review.py            赔率分、分档、build()
    README.md
web/review.py            ← 只剩 7 行兼容 shim（19 个老用例按老名字 import）
web/db.py                ← 负责取数：merged() / moats() / financials()
```

`stock_review` 不 import `web`、不连库（`inner()` 那五行复制过来了，否则
`web/__init__ → app → review` 成环）。数据由 `web/db.py` 读好传进去。

**显示哪几条由 `config.GATE_KEYS` 决定**：「算几条」和「显示几条」是同一个开关。

## 二、三条门槛的完整判定

数据全部来自 `shared.db.finance`，没有第二个来源。

### ① 不亏损（`gate_profit`）

```
cut_ttm  > 0                 扣非 TTM（最近四季单季扣非之和）
且 cut_q >= 0                最新单季扣非不为负
且 cut_cum / np_cum >= 0.80  扣非 / 归母 ≥ 80%
```

| 项 | 说明 |
|---|---|
| 数据字段 | `NPDeductNonRecurringPL`、`NPParentCompanyOwners`、`cashflow.NPDeductNonRecurringPL_Q` |
| 阈值 | `GATE1_DEDUCTED_RATIO_MIN = 0.80` |
| 缺数据 | 归母 ≤ 0 或缺失 → 未核实；TTM 凑不齐四季 → 退回累计扣非（口径不同，已知将就） |

**为什么加 80% 那条**：靠政府补助、卖资产转正的公司，报表上不亏，主业在失血。
「扣非为正」挡不住它，「扣非/归母 ≥ 80%」能挡。

### ② 增速（`gate_growth`）

```
rev_yoy_q >= 25              单季营收同比（%）
且 cut_yoy_q > rev_yoy_q     单季扣非同比 跑赢 营收同比
```

| 项 | 说明 |
|---|---|
| 数据字段 | `OperatingRevenueGrowRate_Q`、`NPParentCompanyCutYOY_Q`（都在 `raw_json` 里） |
| 阈值 | `GATE2_REV_YOY_MIN = 25.0` |
| 缺数据 | 任一同比缺失 → 未核实 |

两条缺一不可：只看营收会选到"增收不增利"的铺货型公司，只看利润会被低基数和
一次性收益骗（+161% 可能是去年同季在亏损）。

### ③ 供需（`gate_supply`）

两条证据，**占一条即可**：

```
(a) 毛利率环比连升两季：gm[0] > gm[1] > gm[2]
    gm = (OperatingRevenue_Q - OperatingCost_Q) / OperatingRevenue_Q

(b) 合同负债同比变厚：cl / (rev_q * 4) >= 0.05  且  cl / cl_prev - 1 >= 0.20
    cl   = 最新一季 ContractLiability
    cl_prev = 去年同季（不是上一季）
```

| 项 | 说明 |
|---|---|
| 数据字段 | `OperatingRevenue_Q`、`OperatingCost_Q`、`ContractLiability` |
| 阈值 | `GATE3_CL_YOY_MIN = 0.20`、`GATE3_CL_YOY_FAIL = -0.10`、`GATE3_CL_SHARE_MIN = 0.05` |
| 缺数据 | 三季成本不齐、或合同负债两期不齐 → 该条未核实 |

**合成规则**（矩阵，行 = 毛利率，列 = 合同负债）：

| | 过 | 未核实 | 不过 |
|---|---|---|---|
| **过** | 过 | 过 | 未核实（打架） |
| **未核实** | 过 | 未核实 | 不过 |
| **不过** | 未核实（打架） | 不过 | 不过 |

三个刻意的取舍：

1. **合同负债用同比，不用环比**。它在 Q4 集中确认，环比比出来的是季节性。
2. **必须过 5% 的占比门槛**。这批 311 只的合同负债中位数只有年化营收的
   **2.4%**，小基数上翻一倍只是噪声（健民集团 3286 万，占营收 1.2%）。
3. **两条打架时不下结论**：毛利率在涨、订单在缩，可能只是原材料降价 →
   落「未核实」，交给人看。

**坚决不加的东西**：提价公告、交期拉长、产能受限。共享库里没有这些字段，
加进来只能靠手写备注，等于把判断建立在数据库之外。

## 三、三态与页面呈现

| 状态 | 颜色 | 含义 |
|---|---|---|
| `pass` | 绿 ✓ | 明确满足 |
| `fail` | 红 ✗ | 明确不满足 |
| `unknown` | 灰 ? | 数据缺一季，或两条证据打架。**既不算过也不算不过** |

`unknown` 不扣分、不降档、不进「提示」列——工具不知道的事不替人做决定。

页面上的三处：

* **「超级成长股标识」列**（旧名「门槛」）：每行四个字，`盈利✓ 增速✗ 供需✓`，
  悬停显示阈值 + 读数 + 理由。
* **顶部三张卡**：各自「过 / 不过 / 未核实」只数。
* **汇总行**：`这一批门槛全过 9 只（中粮资本、金科环境、…），明确不过 288 只…`
  ——全过的票直接把名字写出来，超过 12 只显示前 12 只 + 等。

**没有改的**：分档还是只看质量，档内排序还是赔率分 → 弹性 → Q → 代码，
「提示」列一个字没动。加门槛前后都是 9 / 60 / 86 / 156。

## 四、几个数为什么这么定

### 25% 不是 40%

用户的原话是 40%，但照字面执行会筛掉他自己举的那个例子（营收 +33%、
扣非 +75%、Q3 扣非 +161%）——模组行业是"老业务价格战拖累总量、新业务爆发"，
总量增速天然低于结构增速。

现在总量这条留 25% 的底线。**要回到 40% 就改 `GATE2_REV_YOY_MIN = 40.0`**，
代价是拐点型公司全没。

### 第 ④ 条「新东西」为什么整条删掉

判断"新产品有没有量产"需要看财报正文，数据库里没有这个字段。第一版用
`state/review_evidence.json` 手填，结果是 311 只里 0 过、311 未核实——
那张卡永远是 `0/311`，只有噪声。

2026-11-20 整条删除，代码和证据文件一并删掉。要恢复，得先让
`stock_data_fetch` 把新业务收入抓进库，而不是再加一个手填文件。

### 供需为什么要两条证据

只看毛利率会漏掉一类公司：价格没动、但订单明显变多（预收款在涨）。
只看合同负债会误判小基数。两条一条堵一个洞，打架时又都退回到「未核实」。

## 五、这一批（2026-11-16，311 只）的实测

| 门槛 | 过 | 不过 | 未核实 |
|---|---|---|---|
| 不亏损 | 182 | 125 | 4 |
| 增速 | 27 | 276 | 8 |
| 供需 | 63 | 81 | 167 |

供需的 63 只「过」里：9 只两条都满足、37 只靠毛利率、17 只**只靠合同负债**；
另有 8 只因两条打架落「未核实」。

汇总：门槛全过 **9 只**，明确不过 288 只，没有明确不过但还有门槛没核实 14 只。
分档仍是 9 / 60 / 86 / 156，一只都没动。

数据覆盖：财务 311/311、单季营收同比 303、单季扣非同比 304、季度成本 292、
合同负债两期齐全 299。缺的全部落「未核实」，不猜。

## 六、三件要你拍板的事

**1. 门槛要不要真的排除**

现在是「只标识」。想改成否决，在 `stock_review/review.py: evaluate()` 里加一个
分支即可。建议先只标识跑两周，看你自己会不会照着方块做决定，再决定是否自动化。

**2. 40% 要不要回到总量上**

见第四节。一句话：改了就没有拐点型公司了。

**3. 门槛和赔率分其实在打架**

赔率分奖励"小市值 + 估值低位 + 周期底部 + 弹性强"。高景气股恰好相反：
利润 +161% 的公司 PE 分位往往在 80% 以上，也基本不在周期底部，会被系统性
压到「观察」档。

现在两套逻辑并排放着没打架，是因为门槛不参与排序。**如果以后要让门槛影响排序，
正确做法不是"门槛加分"，而是在「优先研究」档内开一个"景气优先"的排序开关**。

## 七、还能改的（按性价比）

**P0 数据补全**

| 问题 | 现状 | 建议 |
|---|---|---|
| 没有扣非 TTM 字段 | 最近四季 `NPDeductNonRecurringPL_Q` 求和，缺一期退回累计扣非 | `finance` 加 `NPDeductNonRecurringPL_TTM` |
| 季度成本缺 19 只 | 银行/券商没有营业成本 → 供需永远未核实 | 金融股单独一条判定路径，或标「不适用」 |
| 单季同比每次 parse JSON | 0.3s/批，能接受但白费 | 三个同比落成列 |

**P1 口径将就的地方**

1. **增速只看单季**，容易被并表季度或低基数骗。建议加"两年复合增速"或
   "连续两季 ≥ 25%"。
2. **供需的毛利率用环比**，Q4 集中确认会导致失真。可以改成同比连升两季。
3. **扣非/归母用累计值**，Q1 只有一季，噪声大。等 TTM 字段到位后换口径。

**P2 页面**

* 标识列支持点击筛选（`?gate=supply`）。
* 加一列「证伪信号」：毛利率环连降、增速失速——现在只有买的条件，没有卖的。
* 汇总行的「明确不过」也可以像「全过」一样把名字列出来（现在只有数字）。

## 八、会咬人的地方

* **低基数**：扣非 +161% 很可能是去年同季在亏损。②挡不住，①能挡一部分。
* **并表**：收入增速里如果有收购来的，②会被骗。看"内生增速"或商誉变动。
* **合同负债的季节性只解决一半**：同比避开了 Q4，但并购并表、单一大单预收
  仍会让同比失真。5% 占比门槛挡的是小基数噪声，挡不了这个。
* **数据源口径**：`raw_json` 是腾讯口径，和东财/同花顺的单季拆分偶有差异，
  对不上时以定期报告为准。

---

## 九、一句话

门槛的价值在**逼你先回答三个问题**，不在于让工具替你排除。所以这版把它做成
表格里的一列，而不是一道闸——你盯着那三个方块读财报，比盯着一个"已排除"
的红标有用。
