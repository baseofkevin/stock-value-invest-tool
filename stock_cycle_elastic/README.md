# 周期弹性初筛工具

在 A 股里找出：**哪些公司"像周期股"、"弹性大"、"现在处在周期低位"**。

只回答三个问题，各用一个指标，**不做别的**：

```
是不是周期股   ← 最近 20 季单季毛利率标准差 ≥ 5pp（或变异系数 ≥ 20%）
弹性           ← 最近 8 季「利润增速 ÷ 收入增速」中位数 ≥ 2.0
周期位置       ← 产能周转率的 40 季（10 年）分位：<40% 低位 / >60% 高位
```

**给标签、不给分数、不排序。** 工具只负责把标签摊在桌上，权重和结论都由人来做。

数据来自共享数据层 `stock_data_fetch`（`../stock_data_fetch/`），本工具不直连任何上游。
每只股票只缺一次数据：库里有了就读，没有才取。零第三方依赖，只用 Python 标准库。

## 快速开始

```bash
# 单只（代码或名称都行）
python3 cycle_report.py --stock 600519
python3 cycle_report.py --stock 贵州茅台

# 批量：用结果库里那一天的选股名单（推荐）
python3 cycle_report.py --from-select 2026-11-13 --workers 4

# 批量：用自己的一份 CSV（含「代码」列，名称列可选，只读）
python3 cycle_report.py --csv examples/示例-股票清单.csv --workers 4
```

结果写进 `results.db` 的 `cycle_result` 表，用 `./run.py web` 的「周期」页或
`/stock/<代码>` 看（2026-11-15 起不再往磁盘写 HTML / 索引页）。

单股那份报告（三个判断表 + 三段「判断含义」+ 三张 SVG 指标图）仍由本工具渲染
（`cycle/render.py`），渲染结果压进 `payload.report_html`，看板
`/stock/<代码>/report/cycle` 原样吐出来。

```sql
symbol name is_cycle gm_std_pp gm_cv elasticity elastic_label
position_pct position_label payload        -- payload 是完整 JSON，含三判断的原始数值
```

同一基准日重跑时，库里已有的票直接复用（`--force` 才重算），所以"跑一半断了"
再跑一遍不会重复取数。

首次用**名称**（而非代码）查询前，需要先拉一次本地名称表：

```bash
python3 cycle_report.py --refresh-names
```

否则 `--stock 贵州茅台` 会报「本地名称表为空」。这是有意的：名称→代码的映射
来自共享库的 `profile` 域，不在代码里硬编码，避免退市/改名后的陈旧数据。

## CLI 参考

| 选项 | 说明 |
|---|---|
| `--stock CODE\|NAME` | 单只模式，代码或名称都行 |
| `--from-select [日期]` | 批量模式，用 `results.db` 里这一天的选股名单（省略日期=最近一次） |
| `--csv PATH` | 批量模式，CSV 需含「代码」列，「名称」列可选 |
| `--workers N` | 批量并发数（默认 4） |
| `--force` | 忽略库里已有结论全部重算（默认复用当天已有的） |
| `--quiet` | 只输出错误 |
| `--name NAME` | 覆盖报告里的公司名（单只模式） |
| `--bundle JSON` | 离线重放快照（测试 / 无网时用） |
| `--refresh-names` | 刷新本地股票名称表 `data/stock_names.csv` |
| `--stats --sample 500` | 随机抽样只出统计，不产报告（校准阈值用） |

### 取数调优参数已删除

原版有 `--timeout` / `--retries` / `--retry-wait`，控制 node 客户端的 HTTP 行为。
迁移到共享数据层后，超时与限流由 `stock_data_fetch` 的 Throttle 统一接管、
重试由本工具的 `_ensure_retrying` 负责（只对空表重试，最多 4 次）——
**这三个参数调了也没用**，所以删掉。

留着不生效的选项比删掉更误导人：用户会以为「把 `--retries` 调到 5 就能多试几次」，
实际什么都不变。现在传它们会直接报参数错误（退出码 2），不会静默忽略。

### 没有输出目录

**没有 `--out-dir`，也没有报告目录。** 结论只写 `results.db`，
`./run.py web` 读它。以前允许自定目录，于是同一个工具的报告散在 `~/Downloads`、
源码目录、`/tmp` 好几处，"哪份最新"只能靠翻 mtime 猜。

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功（含「历史不足但仍给标签」） |
| 1 | 批量中有失败行（**重复行不算失败**） |
| 2 | 参数错误 / 名称歧义 / 代码无法识别 / 取数失败 |
| 3 | 未预期异常 |
| 130 | 用户中断（Ctrl-C，已算完的已入库） |

## 方法论：三个判断，三个指标

**设计原则：一个判断，只给一个指标。宁可漏，不可繁。**

这是本版最重要的约束。不给辅助指标、不给降级通道、不给多口径交叉验证；
不做综合评分、不做排序、不做池子归类。指标越多，人越容易被数字淹没，
反而看不清"这家公司到底是不是我要找的"。

三个指标全部来自**同一张利润表 + 一张资产负债表，零额外数据源**。

### 判断① 是不是周期股 → 毛利率 5 年标准差

最近 **20 季**（5 年）单季毛利率的标准差。两条通道，**OR** 关系：

| 通道 | 条件 | 通过即判 |
|---|---|---|
| A（绝对） | `σ ≥ 5.0 pp` | 是 |
| B（相对） | `CV = σ / |毛利率中位| ≥ 20%`，且 `毛利率中位 ≥ 5%`，且 `σ ≥ 2.0pp` | 是 |

两条都不过 → 否。

#### 两档到底是什么意思

- **是（周期股）**：毛利率在 5 年窗口里摆动明显。说明产品价格有周期性、
  或者成本端有周期性 —— 这是周期股的定义性特征，不是"业绩差"。
- **否（非周期）**：毛利率稳定。可能是消费品牌（定价权稳）、也可能是
  公用事业（价格管制）。**"否"不等于"不好"**，只是"用周期框架看它没用"。

### 判断② 弹性大不大 → 利润增速 ÷ 收入增速

最近 **8 季**，逐季算「营业利润**环比**增速 ÷ 营业收入**环比**增速」，取中位数。
这就是经营杠杆 DOL 的经验估计。

用**环比**不用同比：8 季里能凑出 7 个环比样本，同比只有 4 个，中位数更抗单季异常
（`cycle/metrics.py` 的 `elasticity()` 里是 `quarters[i] / quarters[i-1]`）。
而"营收长期不动时这个比值没意义"那一条另用**同比**中位数判断，见下表第三行。

| 结果 | 条件 |
|---|---|
| 弹性强 | 比值中位数 `≥ 2.0` 且比值可靠 |
| 弹性弱 | 比值中位数 `< 2.0` 且比值可靠 |
| 比值不稳定 | 营收**同比**增速中位数 `< 3%`（分母趋零，比值无意义），或跨零样本占比 `> 1/3` |

#### 三档到底是什么意思

- **弹性强**：收入涨 1%，利润涨 2% 以上。周期上行时利润放大得厉害。
- **弹性弱**：收入涨 1%，利润涨不到 2%。成本刚性低、或费用摊得薄。
- **比值不稳定**：算得出来但**没有意义**。营收几乎不动时分母趋零，比值会爆；
  营业利润跨零时 DOL 数学上趋于无穷。说它"弱"是凭空下结论。

> 三档互斥。`不稳定` **取代** `强`/`弱`，不是叠加标记 —— 见 [标签怎么读（看板）](#标签怎么读看板)。

### 判断③ 在周期哪个位置 → 产能周转率的 10 年分位

产能周转率 = **最近 4 季营收之和 ÷ 当季（固定资产 + 在建工程）**。
取最近 **40 季**（10 年）的**中位秩分位**。

| 结果 | 条件 |
|---|---|
| 低位 | 分位 `< 40%` |
| 中性 | 分位落在 40%–60%，**不出徽章** |
| 高位 | 分位 `> 60%` |
| 不适用 | 行业命中 `银行/保险/证券/多元金融` |

同时给一个**方向标记**（不参与判断，只帮助解释）：

| 标记 | 条件 |
|---|---|
| 扩产中 | 近 8 季（2 年）总资产增长 `≥ 15%` 且营收不降 |
| 产能在退 | 近 8 季总资产缩水 `≥ 5%` |

#### 三档到底是什么意思

- **低位**：产能利用率处自身历史偏低区，供给端**可能**已出清。
  注意：这不代表营收低，也不代表需求回暖。
- **高位**：产能利用率处历史高位，供给端在满负荷甚至扩张。
- **中性**：中间地带本来就没信息，所以不给标签 —— 这是刻意的，不是漏了。

> **必须连同方向一起读。** 周转率低可能是需求走了（真出清，好），
> 也可能是产能刚投产、营收还没跟上（扩产压低，另说）。方向标记区分这两种。

#### 合同负债（预收款）：为什么只并入判断③

看板（`/cycle`）会在「位置」后面再挂一句需求端限定语，例如
「低位 · 订单回升」。数据是 `ContractLiability` 同比（比去年同季，避开 Q4
集中确认的季节性），占年化营收 ≥ 2% 才认（这批 113 只的中位数是 1.5%），
≥ +20% 记回升、≤ −10% 记走弱。

**先说清楚边界**：下面"设计取舍"里那条实测结论仍然成立——合同负债领先性
只在 3/7 个行业成立（k=4 时 r=0.38），所以它不改变任何标签、不进阈值契约。
这里给的是**事实限定语**（预收款同比变了多少），不是"需求要回暖"的预测。

它**不进判断①、也不进判断②**，理由是三个判断问的是三件不同的事：

| 判断 | 问的是 | 塞进合同负债会怎样 |
|---|---|---|
| ① 是否周期股 | 毛利率**在摆动**吗（5 年 σ / CV） | 合同负债摆的是订单，不是毛利率。硬并进来，军工、工程这类"订单型"公司会被判成产能周期股——它们的波动来自订单节奏，不是产能。要这么改得先重新标定，不能顺手塞 |
| ② 弹性比值 | Δ营业利润% ÷ Δ营收%（损益表口径） | 分子分母都来自损益表，比值可以复算。混进一个资产负债表项，这个数就没法复算了，DOL 也不再是 DOL |
| ③ 位置 | 产能周转率在自身十年里的分位（供给端） | **正好补它缺的那一半**：分位只说供给端松紧，不说需求在不在回来 |

所以做法和工具里已有的「扩产中 / 产能在退」完全一样：**只加限定语，不改标签**。
位置仍由分位决定，合同负债只回答"这个低位是需求在回来，还是还在往下掉"。
分位算法、11 个判定阈值、`decide()` 的五个 key 都没动。

> 现状：这一层目前合并在**看板**（`web/app.py: _demand_suffix`）里做，工具本体
> 的报告和入库还没有这条。要让它进报告，得先扩阈值契约（多一个"占比门槛"和
> 两个方向线），再重跑全批——那是另一件事。

### 三个指标合起来怎么读

```
周期股 + 弹性强 + 低位（+ 产能在退）   ← 教科书式的"周期底部"
周期股 + 弹性强 + 低位（+ 扩产中）     ← 周期底部但在扩产，赌的是下一轮
周期股 + 弹性弱 + 低位                 ← 可能已经"去周期化"，或者下行还没到底
非周期 + * + *                         ← 换框架看，别用周期思路
```

**工具不替你下结论。** 上面四行是读法示例，不是分类规则。

## 参数全表

全部阈值集中在 `config.py`。**一共 11 个判定阈值 + 5 个窗口**。

### 数据窗口

| 名称 | 值 | 说明 |
|---|---|---|
| `HISTORY_QUARTERS` | 44 | 一次取的季度数：40 季（10 年）+ 4 季冗余（算同比） |
| `WAVE_WINDOW_QUARTERS` | 20 | 判断① 毛利率标准差的窗口 = 5 年 |
| `ELASTIC_WINDOW_QUARTERS` | 8 | 判断② 比值中位数的窗口 |
| `POSITION_WINDOW_QUARTERS` | 40 | 判断③ 分位的窗口 = 10 年 |
| `YOY_PERIODS` | 4 | 同比 = 4 个季度前（只用于判断②的「不稳定」判定，比值本身是环比） |

### 判定阈值（只有 11 个）

| 参数 | 值 | 依据 | 用在哪 |
|---|---|---|---|
| `GM_STD_CYCLE` | 5.0 pp | 东北证券：毛利率 5 年窗口标准差 > 5pp 判周期 | 判断① 通道 A（绝对） |
| `GM_CV_MIN` | 20.0 % | 113 只实测：低毛利组命中率 35%→89%，高毛利组 58% | 判断① 通道 B（相对） |
| `GM_MEDIAN_MIN` | 5.0 % | 守卫：中位接近 0 时 CV 分母趋零会爆炸（实测 1 只到 354%） | 判断① 通道 B 守卫 |
| `GM_STD_MIN_FOR_CV` | 2.0 pp | 守卫：绝对波动太小的（如纯冶炼）不该靠相对通道进来 | 判断① 通道 B 守卫 |
| `ELASTIC_RATIO_MIN` | 2.0 | DOL 常用高杠杆分界 | 判断② |
| `REV_MEDIAN_STABLE_MIN` | 3.0 % | 工程经验：营收增速中位数低于此值，比值不稳 | 判断② 可靠性 |
| `ELASTIC_ZERO_CROSS_MAX` | 0.3333 | 实测 904 个逐季对里 135 个（15%）营业利润跨零，DOL 在盈亏平衡点趋于无穷 | 判断② 可靠性 |
| `POSITION_LOW_PCT` | 40.0 | 招商策略 30%「出清确认」口径的放宽版 | 判断③ |
| `POSITION_HIGH_PCT` | 60.0 | 同上 | 判断③ |
| `CAPACITY_EXPAND_GROWTH` | 15.0 % | 2 年资产增长 ≥15% 且营收不降 → 「扩产中」 | 判断③ 方向标记 |
| `CAPACITY_SHRINK_GROWTH` | -5.0 % | 2 年资产缩水 ≥5% → 「产能在退」 | 判断③ 方向标记 |

> **判断① 为什么从 1 个阈值变成 4 个。**
> 原来的口径是纯绝对尺度：σ ≥ 5pp 就是周期股。问题是**毛利率水平低到十几个点的公司，
> σ 在数学上就到不了 5pp** —— 毛利率在 0 和景气高点之间摆动，σ 的上限大约是中位数的
> 0.7 倍。实测 113 只：毛利率中位 < 10% 的 17 只里只有 35% 过线，而 ≥10% 的 95 只是 49%。
> 同一把尺子，低毛利生意天然吃亏。
>
> 增设的通道 B 用**相对波动**（变异系数 CV = σ / |毛利率中位|）来判断同一件事：
> 毛利率 15% 的公司摆动 4pp（CV≈27%）跟毛利率 40% 的公司摆动 11pp 是一回事。
> 换成相对口径后，低毛利组命中率回到 89%，两组的待遇才拉平。
>
> 两个守卫不是"多两条标准"，是防脏数据：中位数接近 0 时 CV 会因分母趋零爆成几百；
> 绝对波动极小的公司（毛利率 2-6% 之间晃的纯冶炼）用毛利率量它本来就选错了指标，
> 不该被相对通道漏进来。
>
> 两个通道是 **OR**，不是加权：它们回答的是同一个问题，只是各用自己把握得住的尺子。
> 加权要引入权重，而权重没有客观依据（同「为什么不排序、不打总分」）。

> **`GM_STD_CYCLE` 的季度化校准还没做**（唯一未完成项）。
> 东北证券的 5pp 是「5 年窗口、**年度或滚动**口径」，本工具用**季度单季**毛利率，
> 同一家公司的季度值通常更抖（季节性、收入确认节奏），直接照搬大概率偏高。
>
> - 做法：`--stats --sample 500`（固定 seed，可复现，约 13 分钟）看分布，
>   把命中率校准到 **20–40%**。
> - 高于 50% → 门槛太松，几乎人人都是周期股，失去区分力；
>   低于 10% → 门槛太紧，真周期股被漏掉。
> - **一次校准即可，不要反复调。** 调来调去的结果是「只有作者知道为什么命中」，
>   那就不可复现了。结论写进 `config.py` 注释，注明样本日期与命中率。

### 参数不漂移的保证

`test_config_contract.py` 逐条断言：

1. 上表每个参数名都在 `config.py` 存在（**防文档漂移**）。

## 数据接口

### 共享数据层（唯一数据源）

| 域 | 拿什么 | 走哪个函数 |
|---|---|---|
| `finance` | 利润表 `OperatingRevenue_Q` / `OperatingCost_Q` / `OperatingProfit_Q`，资产负债表 `TotalFixedAsset` / `TConstruInProcess` / `ContractLiab` | `h.ensure()` + `h.finance_full()` |
| `profile` | 股票名称、行业（用于金融企业识别） | `h.read("profile", ...)` |
| `scan` | 全市场代码/名称表（`--refresh-names`） | `h.scan()` 读 `symbol`/`name` 两列 |

三条不变式（由共享层保证，本工具依赖它们）：

1. **只有 raw 不复权**。财务数据没有"复权"概念，但这条是防未来有人混入带调整的口径。
2. **财报 append-only**。同一 `(symbol, period)` 不会因为重取而改变历史。
3. **数据与 coverage 同事务**。要么都写进去、要么都没写，不会出现"有数据但不知道覆盖到哪期"。

### 期数：`RAW_JSON_KEEP = 43`

共享层每个 `(symbol, period)` 保留最近 **43 期**的原始 JSON。这个数字不是拍出来的：

- 判断③ 要 **40 个**周转率样本（40 季窗口）；
- 周转率 = 最近 4 季营收之和 ÷ 当季资产，**前 3 期凑不满 4 季滚动和**；
- 所以 40 + 3 = **43 是硬下限**，一期都不能少。

上游能给的历史也就 43 期（2016Q1 起），所以 43 同时是"需求下限"和"供给上限"。
实测单期 4.2KB，500 只 × 43 期 ≈ 88MB。

> 曾有一版写成 20，代价是判断③ 静默降级：名义 40 季窗口实际只出 17 个样本，
> 报告照样生成、照样有分位数字，**但那是错的**。这类"不报错的错"最难发现，
> 所以 `config.HISTORY_QUARTERS = 44` 与 `RAW_JSON_KEEP = 43` 的差值有测试盯着。

### 代码归一化

`cycle/codes.py` 统一处理各种写法，输出 6 位数字 + 交易所：

| 输入 | `parse()` | `market()` | `with_prefix()` |
|---|---|---|---|
| `600519` | `600519` | `sh` | `sh600519` |
| `sh600519` | `600519` | `sh` | `sh600519` |
| `600519.SH` | `600519` | `sh` | `sh600519` |
| `000001` | `000001` | `sz` | `sz000001` |
| `920001` | `920001` | `bj` | `bj920001` |

北交所在东方财富的 URL 是 `quote.eastmoney.com/bj/920001.html`（带斜杠），
沪深是 `quote.eastmoney.com/sh600519.html`（不带）。这个不一致是历史遗留，
`codes.eastmoney_url()` 专门处理，有测试盯着 —— 拼错不会报错，只会跳到 404。

### `EndDate` 为什么要补

共享层的 `finance_full()` 每行带 `period`，但 `build._row_date()` 认的四个键里
**没有 `period`**。`fetch._with_end_date()` 把 `period` 复制到 `EndDate`。
不补的后果不是报错，而是**每一行都被判「日期格式异常，已跳过」**，`quarters=0`，
报告出空表 —— 又是一个"不报错的错"，有测试钉住。

## 计算管线

```
fetch  →  build  →  metrics  →  decide  →  results.db
取数      对齐       三指标       三标签      一行结论
```

### build：两表对齐

利润表和资产负债表的季度日期可能不完全重合（资产负债表按季末，
利润表偶尔缺季），需要按日期对齐成一条 44 季的时间轴。

**Q4 回推陷阱**（曾是个真 bug）：三季报缺失单季拆分时，不能用
「年报 − 半年报」当 Q4 单季 —— 那得到的是"下半年"，混进了 Q3。
缺失就整季置 `None`，宁可少一个点，不要造一个错点。

日期校验也有坑：`\d{2}` 会放过 `2025-13-45`。改为真正解析到 `datetime.date`。

### metrics：三个纯函数

无副作用、无 IO、无全局状态。同样输入永远同样输出 —— 这是可测试性的前提。

零营收时不产生 `0.0` 而是 `None`：0 是有效业务值（真的没卖出去），
`None` 是"算不出来"。混为一谈会让分位计算把假零点算进去。

### decide：十一个阈值

判断① 是双通道（绝对 σ / 相对 CV），两条是 OR 关系；`channel` 字段记录
是哪条过的，只用于解释，不参与判断。另外两个守卫挂在通道 B 上。

`meta.quarters < MIN_QUARTERS_REQUIRED` → 标「历史不足」，但仍出报告。
判断是初筛，不是准入 —— 数据少也该让人看见。

这也决定了 `fetch_finance` 里 `min_points=1` 而不是 40：期数不够由 `decide`
标「历史不足」，不该在取数层抛 `InsufficientDepth` 把整只票判死。

### 落库

`decide` 出来的三个标签加上几个能直接查的读数，一行写进 `results.db`；
完整数值（44 季序列除外）留在 `payload` 里。展示交给看板——
换一种画法不需要动计算代码。

## 标签怎么读（看板）

看板的「周期」页与单只页展示的就是三个判断的结果，颜色与徽章语义固定：

| 徽章 | 颜色 | 含义 |
|---|---|---|
| `周期股` | 主色 | 毛利率 σ ≥ 5pp（或 CV 通道通过） |
| `非周期` | 灰 | 两条通道都不过 |
| `弹性强` | 主色 | 比值 ≥ 2.0 且可靠 |
| `弹性弱` | 灰 | 比值 < 2.0 且可靠 |
| `低位` | 绿 | 分位 < 40% |
| `高位` | 红 | 分位 > 60% |

辅助标记（不参与判断，只解释为什么某项是空的）：

| 标记 | 颜色 | 含义 | 与徽章的关系 |
|---|---|---|---|
| `比值不稳定` | 琥珀 | 营收增速中位数 < 3%，比值不可信 | **取代** `弹性强`/`弹性弱`（`elastic_label="unstable"`），三者互斥 |
| `不适用` | 灰 | 金融股，产能周转率无意义（`position_label="na"`） | 取代 `低位`/`高位` |
| `历史不足` | 灰 | 季度数 < 20 | 只加标记，不取代判断① 的结论 |

> **`弹性弱` 与 `比值不稳定` 必须分开**：早期设计把两者合并成「弹性弱」，这是错的
> —— 营收几乎不动时比值算得出来但**没有意义**（分母趋零），说它「弱」是凭空下结论。
> `unstable` 是「不知道」，`weak` 是「知道且不强」，两者语义不同、颜色也不同。

分位落在 40–60 之间时不出标签（中性不给标签），这是刻意的：中间地带本来就没信息。

看板「周期」页还会在「位置」徽章后面挂一句**需求端限定语**（「订单回升」/
「订单仍弱」/「需求转弱」…）。那**不是徽章**，也不改变上面任何一个标签——
来源是合同负债同比，规则见「判断③」那节。

**空数据不整行消失。** 任一判断数据缺失时，页面上该格写 `—`，
并在单只页的「数据缺口」里写原因（如 `需 8 季，现有 5 季`）。次新股必然缺 10 年
数据，直接报错等于放弃一整个股票池。

**数值一律不为空串以外的东西。** `None` / `nan` / `inf` 一律给 `—`，
`fmt_*` 系列都有 `math.isfinite` 守卫，上游 0/0 不会漏成字符串 `"nan"`。

**视觉规范**（抄自原来的报告，看板沿用同一套）：主色墨绿 `#2f6152`，
低位绿 `#1f7a4d`，高位红 `#b3261e`，警示琥珀 `#9a6700`。

## 设计取舍

**为什么不排序、不给总分。** 三个维度彼此正交，"周期股 + 弹性强 + 低位"听起来
最理想，但把它加成一个分数就隐含了权重，而权重没有客观依据。给标签、不排名，
剩下的判断留给使用者。

**为什么合同负债不进判断，只做限定语。** 16 只 × 13 行业实测，覆盖率 16/16，
但"合同负债增长领先营收增长"只在 3/7 个行业成立（k=0 时 r=0.61，k=4 衰减到 0.38）。
证据不够硬，所以它**不影响任何一个标签**，也不产生新标签、不进阈值契约。

2026-11-20 起，看板在「位置」后面挂一句**事实描述**（「订单回升」/「订单仍弱」），
说的是"预收款已经变了"，不是"需求会回暖"——那个更弱的预测结论正是上面被否掉的。
线上实现只看板层（`web/app.py: _demand_suffix`），报告和入库仍然没有这条。

**为什么完全不提财务杠杆。** 18 只实测 DFL 中位数跨公司极差只有 0.075
（标准差 0.016），与资产负债率还呈负相关（r=−0.33），亏损时直接变号失效。
零信息量的指标放上去只会增加干扰。需要杠杆请自己看资产负债率。

**为什么用增速比值中位数而不是滚动回归。** 等价地刻画"典型放大倍数"，
代码量降一个量级，还没有回归的窗口长度、最小样本、共线性这些额外决策。

**为什么只判方向不判强度。** 三个阈值全是经验/文献分界，不做精细标定 ——
初筛工具标定得越精细，越容易给出一种"精确"的假象。

**为什么取数走共享库而不是自己调。** 四个选股工具（kline / quality / cycle /
judge-top）看的是同一批股票、同一批财报。各自直连上游的后果是同一份财报一天被
拉四遍，还要各自写节流和退避。共享层的 `ensure()` 命中即返回，缺才取 ——
第二、三、四个工具基本零网络。

## 被删掉了什么，为什么

从上一版（A/B/C/D 四维、10 个指标、4 个池）删到这一版（3 个判断、3 个指标、
3 个标签），逐项记账：

| 删掉 | 原用途 | 为什么可以删 |
|---|---|---|
| **B 维度（10 年极差 15pp/10pp）** | 与 A 并列的第二个波动判据 | **和①是同一件事的两种测法**。都是"波动大 = 周期股"，只是一用标准差、一用极差。标准差信息量更大（极差只由两个点决定） |
| **利润增速标准差** | A 的辅判据 | 毛利率一个指标已能判定；利润增速噪音大，加它只提高假阳性 |
| **A 的降级通道（3.5pp）** | 让接近门槛的也进 | 多一个阈值就多一个要解释的分支。要么就 5pp，要么就不算 |
| **偿债风险（有息负债/经营现金流）** | 过滤爆雷 | 不属于三问中任何一个。判断它还要处理分母正/负/缺失三种分支，代价大于价值 |
| **净利率 < 5% 标记** | 近似"接近盈亏平衡" | DOL 在 EBIT→0 时天然趋于无穷，这个标记想表达的"低利润率=高弹性"已包含在②里 |
| **财务杠杆系数** | 借钱放大 | 实测 DFL 跨公司极差仅 0.075，几乎恒等于 1.00；与负债率负相关；亏损时变号失效。**不是"留给人看"，是零信息** |
| **合同负债 / 订单线** | 判断需求是否回暖 | 实测相关系数显示它更像同期/弱领先指标（k=1 时 r 从 0.61 降到 0.59，k=4 降到 0.38），不足以支撑"需求正在回暖"的结论；而"需求"不在三问之内 |
| **商品类/金融股降级分支** | 口径修正 | 没有订单线就没有"商品类不适用"的问题。金融股仍需要一个标记，但那是 1 行 `if`，不是一个分支体系 |
| **四池归类 / 综合成本** | 归类 | 用户明确要求"给标签不排序"，池子归类是排序的前身 |
| **`providers/westock_client.js`** | 直连 MCP 的 node 转发层 | 取数已交给共享数据层。留着它就等于留了一条绕过节流和缓存的旁路 |
| **`--out-dir`** | 自定输出目录 | 报告取消后没有目录这回事，结论只进 `results.db` |
| **单股 HTML / 索引页 / 模板** | 人看的报告 | 看板统一出，四个工具各自画一份等于四套口径。结论进库、展示归看板 |
| **`--timeout` / `--retries` / `--retry-wait`** | 调 node 客户端的超时与重试 | 超时由共享层 Throttle 管、重试由 `_ensure_retrying` 管。**调了也没用**，留着只会误导 |

**指标数：10 → 3。阈值数：14 → 11。分支数：四池 + 三类降级 → 1 个金融股标记。**

## 取数失败与重试

批量跑 100+ 只时总会有几只失败。**先别急着当成"数据缺失"** —— 实测 113 只
自选股里首轮失败的 11 只，重跑后全部成功。它们不是没有数据，是取数抖了一下。

### 现在由两层负责，职责不重叠

| 层 | 管什么 |
|---|---|
| 共享层 `stock_data_fetch` | 节流（跨线程闸门）、缓存命中判断、上游错误分类 |
| 本工具 `_ensure_retrying` | **只对「上游返回空表」重试**，最多 4 次，间隔 1.5 秒 |

**为什么只重试空表**：`EmptyResult` 是"库里没有、上游这次也没给"，
典型原因是限频或服务端降级 —— 这些是瞬时的，等一下就有。
而 `SourceUnavailable`（接口改名）、`PartialData`（限频后仍缺）重试也没用，
重试只会让整批更慢。

**为什么共享层不自己重试空表**：它不知道"这只票的财报一定存在"。
对指数、对新股，空表是合法终态。所以重试策略必须由**知道业务语义的调用方**决定。

> 曾经踩过的坑：`_ensure_retrying` 重试用尽后抛的是共享库的 `EmptyResult`，
> 而 CLI 只捕获本模块的 `DataError`，于是栈回溯直接吐到用户脸上。
> 现在 `fetch_finance` 里统一翻译成 `DataError`。

### 实际影响

首轮 113 只 → 102 成功 / 11 失败；重跑这 11 只 → 全成功。
按旧逻辑（`retries` 对空表无效、退避 60 秒），这 11 只的代价是
**11 × 2 × 60 = 22 分钟纯等待，然后仍然失败**。

**仍建议的做法**：批量跑完用「CSV 代码列表 vs 实际报告文件名」比对一次，
比看索引页的失败计数可靠 —— 索引页只反映当轮状态，而报告可能早就落盘了。

## 已知边界

写在报告脚注里，不藏：

1. **周期位置只看供给端。** 低位 = 产能利用率处自身历史偏低区、供给端可能已出清，
   **不代表**营收低、也**不代表**需求回暖；高位反之。
2. **分子是营收不是产量。** 产品涨价会让周转率虚高（可能误判"高位"），
   跌价会虚低（误判"低位"）。这是拿不到产量数据时的代理指标，看的时候心里要有数。
3. **周期性只测了三判据中的一个。** `是` 不等于"确定是周期股"。
4. **毛利率标准差用的是季度值。** 季节性会让季度标准差偏高，对季度口径偏松。
5. **判断① 的绝对口径对低毛利公司偏严，已由相对波动通道补偿，但补偿不完整。**
   毛利率中位 < 5% 的公司（纯冶炼加工、大宗贸易）两条通道都量不出价差波动 ——
   它们的周期体现在营业利润上（实测云南铜业毛利率 σ 仅 0.99pp，但 20 季营业利润
   从 −0.69 亿到 17.46 亿）。这类公司由「①否②强·存疑」标记提示，判断① 本身
   不再为它们增设通道（否则要加第四个判据，违反「三个判断」的设计约束）。
6. **「低位/高位」必须连同产能方向一起读。** 周转率低可能是需求走了（真出清），
   也可能是产能来了（扩产压低）。工具用「扩产中/产能在退」区分，但它只覆盖
   「近 2 年资产变化」这一层 —— 项目投产节奏、资产减值、并购都会干扰方向判断。
7. **「不稳定」的比值仍然显示。** 那是刻意的：数值本身有信息（比如知道它
   在盈亏平衡点附近），只是不该拿来比强弱。
8. **弹性是纯经营杠杆**，不含财务杠杆。
9. **历史深度受上游限制。** 共享层最多保留 43 期，2016Q1 之前的数据拿不到；
   2016 年后上市的公司，判断③ 的窗口必然不满 40 季。
10. **所有标签是初步筛选，不构成买卖建议。**
