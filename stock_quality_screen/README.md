# 企业质量初筛工具

输入一个股票代码（或一批代码），算出质量分 Q、估值分 V、14 条风险检查、机构预期，
最后给一句结论。**结果写进 `results.db`**，用 `./run.py web` 的「质量」页或
`/stock/<代码>` 看（2026-11-15 起不再往磁盘写 HTML / CSV）。

单股那份五节报告（生意本身 / 经营质量与风险 / 估值与机构预期 / 综合评分 /
后续跟踪）仍然由本工具渲染（`screen/render.py`），只是**渲染结果压进
`payload.report_html`**，看板 `/stock/<代码>/report/quality` 原样吐出来。

只做**定量初筛**，不做行业研究、不给目标价、不写故事。结论一共 **12 种**：
矩阵里 9 种 + 矩阵之外 3 种，全部由 `config.DECISION_MATRIX` 与
`score._decision()` 决定——说一套、算一套在这个项目里是设计错误，不是笔误。

数据来自共享数据层 `stock_data_fetch`（`../stock_data_fetch/`），本工具不直连任何上游。
零第三方依赖，只用 Python 标准库。

## 快速开始

```bash
cd stock_quality_screen

# 单只股票
python3 stock_report.py --stock-code 600519

# 批量：用结果库里那一天的选股名单（推荐）
python3 stock_report.py --from-select 2026-11-13

# 批量：用自己的一份 CSV（只读，不改动、不产出新文件）
python3 stock_report.py --csv 我的持仓.csv

# 离线重放（不发网络请求）
python3 stock_report.py --stock-code 600519 --bundle tests/fixtures/mini_bundle.json
```

## CLI 参考

`--stock-code` / `--from-select` / `--csv` 三选一，互斥且必填。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--stock-code CODE` | — | `600519` / `sh600519` / `600519.SH` 都认 |
| `--from-select [日期]` | — | 批量模式：用 `results.db` 里这一天的选股名单（省略日期=最近一次） |
| `--csv FILE`（旧名 `--csv-input`） | — | 批量模式：读 CSV 的代码列（`代码` / `股票代码` / `证券代码` / `code`） |
| `--name NAME` | `""` | 覆盖公司名，仅单股模式 |
| `--bundle PATH` | `""` | 离线采集包（旧 raw JSON），不发起网络请求 |
| `--timeout SEC` | `90` | 单次取数超时 |
| `--workers N` | `4` | 批量并发线程数 |
| `--retries N` | `2` | 取数失败后的重试次数 |
| `--retry-wait SEC` | `60` | 重试前等待秒数 |
| `--force` | 关 | 批量模式忽略库里已有结论，全部重算 |
| `--quiet` | 关 | 只输出错误（连取数层的重试警告一起静音） |

**没有 `--out-dir`，也没有报告文件。** 结论只写 `results.db` 的
`quality_result` 表（每行带完整 `payload`），看板读它。表结构 **13 列**
（`primary key(run_id, symbol)`）：

```
run_id  symbol  name  q  q_grade  v  v_grade  conclusion  reason
risks_hit  risks_watch  risks_known  payload
```

`run_id` 指回 `run` 表——同一批重跑会生成新 `run_id`，**续跑复用旧行时
`run_id` 仍然是新的那一个**（`payload` 原样搬过来），所以看板"最新 run"能看到全部票。

顺带解掉了旧设计的一个死结：以前"续跑"靠扫输出目录里已有的 HTML、再用正则把
Q/V 抠回来（`summary.py`）。结论本来就是算出来的 dict，却先渲染成 HTML、再解析回
文本、还要处理解析失败。现在续跑只问结果库有没有这只票的记录。

### 退出码

| 码 | 含义 |
|---|---|
| `0` | 成功（**含「跳过」**：上市不足 3 年不是错误） |
| `1` | 批量模式里**有股票失败**（`return 0 if failed == 0 else 1`） |
| `2` | 用户输入 / 数据问题（代码格式错、取数失败、校验不通过） |
| `3` | 未预期错误（该看堆栈了） |
| `130` | Ctrl-C 中断 |

「跳过」与「失败」必须分开：批量跑 155 只，混进 3 只次新股是常态，不该让整批返回非零。
但**真有股票失败**时批量会退 1（不是 2）——`1` 专指"跑完了、但有票没出结论"，
和"压根没跑起来"的 `2` 区分开。

## 输出形态

**看板**（`/stock/<代码>`）才有一张卡式的一行结论。**CLI 不打那一行**，它打的是：

单只模式（`stock_report.py --stock-code 600519`）最后两行是 Q/V 汇总：

```
  质量分 Q 78.0 / 100   估值分 V 83.8 / 100
```

`Q` / `V` 三种形态要分清：`78.0 / 100`（算出来了）、`不适用`（金融股，
`not_applicable`）、`—`（算不出来）。V 算不出来但**历史分位可用**时会多打一行：

```
  历史分位参考 42.3 / 100（偏低，样本 312 周）· 只展示，不参与结论
```

批量模式：

```
待算 38 只
[  1/38] 贵州茅台 sh600519  观察，第二节有信号
...
批量完成：成功 38 只（复用 0 只），跳过 0 只，失败 0 只，共 38 行
  V 分留空 6 只（没有机构覆盖或缺少预测；Q 分照常算）
  名单    results.db 选股 2026-11-13
  结果    results.db（./run.py web 查看）
```

> `V 分留空 N 只` 这行只在真的有人没 V 时才出现——没有机构覆盖的票天然没有 V，
> 这不是失败，但不说清楚容易被当成出错。
>
> 批量里**跳过**（上市不足 3 年）的票打 `[ n/N] <代码>  跳过：上市不足 3 年`
> 到 **stderr**，不计入"成功"。`--quiet` 关掉除 stderr 错误外的所有输出。

## 评分口径

**质量分 Q**（五个维度，合计 100，`config.QUALITY_WEIGHTS`）：

| 维度 | key | 权重 | 报告里的名字 |
|---|---|---|---|
| 资本回报 | `returns` | 30 | 资本回报 |
| 现金创造力 | `cash` | 25 | 现金创造力 |
| 资产负债表 | `balance` | 20 | 资产负债表 |
| 成长与稳定 | `durability` | 15 | 成长与稳定 |
| 会计质量 | `accounting` | 10 | 会计质量 |

**Q 分档**（`config.QUALITY_GRADES`，下限含；等级只是标签，不参与打分、不改变结论）：

| 下限 | 档名 |
|---:|---|
| 85 | 优秀 |
| 75 | 良好 |
| 65 | 中等偏上 |
| 55 | 中等 |
| 45 | 偏弱 |
| 0 | 差 |

> 分数条配色另有两条线（只影响观感）：≥65 绿、<45 红。`65` 必须等于
> 「中等偏上」的下限、`45` 必须等于 `QUALITY_HARD_FLOOR`，`test_config_contract` 有断言守着。
> 金融股 Q 不计算，`grade` 写 **`金融股不适用`**。

**亏损公司的杠杆项（2026-11-15 修）**：`净负债/EBIT` 在 EBIT ≤ 0 时比值没有
意义——净负债为正会算出负数，`inverse()` 当成"越小越好"给满分 8/8；净负债为负
又会算出正数，反被扣光。现在 EBIT ≤ 0 一律 **0 分**（两个方向都不给）：不赚钱时
这一项不该给分，亏损本身由 ROE / ROIC / 毛利 / 现金那几项去扣。只给净负债那一侧
0 分是不够的——净现金的亏损公司如果拿满分，实测会让 `sh603138` 越过 Q=45 的硬
地板，结论从「回避」松成「数据不足」。第二节的风险检查按同一判据判「亏损 + 净
负债 → 命中」。

**致命项里的「连续 3 年经营现金流为负」（2026-11-15 修）**：这条原本要求
`净负债/EBIT > 4`，但 EBIT ≤ 0 时比值恒为负、`> 4` 永远不成立——**最该命中的
一类公司（三年失血 + 净借债 + 不赚钱）反而绕过了**。现在按方向判：EBIT ≤ 0 时
只要净有息负债 > 0 就命中；EBIT > 0 时仍是原来的比值门槛。净现金的亏损公司不算
（没有靠借钱续命）。实测 38 只里 `sz000782 恒申新材` 因此多命中一条，结论不变
（本来就因「利息保障 < 1」回避），但给出的理由完整了。

**四条致命项**（`score._fatal()`，命中任一 → 结论直接「回避」，不再看 Q/V）：

| # | 判据 | 常量 | 命中文案 |
|:--:|---|---|---|
| 1 | 最新一期净资产 ≤ 0 | — | `净资产为负` |
| 2 | `EBIT / 利息费用 < 1`（仅当利息费用 > 0） | `INTEREST_COVER_FATAL = 1.0` | `利息保障 < 1` |
| 3 | `商誉 / 净资产 > 50%` | `GOODWILL_EQUITY_FATAL = 0.50` | `商誉/净资产超过 50%` |
| 4 | **连续 3 年**经营现金流为负，且（`EBIT > 0` 时 `净负债/EBIT > 4`；`EBIT ≤ 0` 时净有息负债 > 0） | `FCF_NEGATIVE_YEARS = 3`、`FATAL_NET_DEBT_EBIT = 4.0` | `连续 3 年经营现金流为负…` |

第 4 条必须**真有 3 个年报**且 3 年 OCF 都为负——旧写法 `_years(data)[-3:]` 在只有
2 年时切片仍非空，会把 2 年说成 3 年。

现金短债比（`CASH_DEBT_RATIO_FATAL = 0.50`）与净现比**不升级为致命项**，
只在命中后于结论行点名（`RISK_HEADLINE_KEYS = ("cash_flow", "cash_debt")`）——
否则会把"借钱但周转正常"的公司一刀切。

**14 项风险检查**（`score._risk_checks()`，4 组；`RISK_CHECK_COUNT = 14`）：

| 组 | key | 名称 | 严重度 |
|---|---|---|---|
| 真伪 | `cash_flow` | 现金流质量（净现比 TTM 四档 + FCF 负年数） | 高 |
| 真伪 | `nonrecurring` | 利润口径（扣非/归母 < 0.70 视为靠非经常性损益） | 高 |
| 趋势 | `margin_improve` | ① 毛利率环比改善（容差 `MARGIN_IMPROVE_EPS = 0.05` pct） | 高 |
| 趋势 | `contract_liability` | ② 合同负债（同比 ≥20% 且占营收 ≥2%） | 高 |
| 质量 | `ar_gap` | 应收增速差（>15pct 关注；应收/营收 <2% 只记录） | 高 |
| 质量 | `inventory_gap` | 存货增速差（>15pct 关注、>30pct 或连续 2 年高危；存货/营收 <1% 跳过） | 中 |
| 质量 | `cashflow_pattern` | 三流组合（经营/投资/筹资现金流符号组合） | 中 |
| 质量 | `construction` | 在建工程 | 中 |
| 质量 | `per_share` | 每股口径（股本扩张但每股指标没增） | 中 |
| 安全 | `cash_debt` | 现金短债比（<1 紧张、<0.5 高危、>5 显示"无短债压力"） | 高 |
| 安全 | `leverage` | 杠杆（有息负债/现金/EBIT） | 高 |
| 安全 | `interest` | 利息负担（利息保障） | 高 |
| 安全 | `goodwill` | 商誉（/净资产 20% 警惕、30% 命中、50% 致命） | 高 |
| 安全 | `other_receivable` | 其他应收款（/总资产 >2%） | 中 |

每项状态是 `clear` / `watch` / `hit` / `unknown` 四值之一。`unknown` 表示口径不适用或
字段缺失，**不算命中**——所以「已知 9/14」里的分母是 `14 − 不适用项数`，
不是常数 14（金融股有 5 项直接标不适用，见 `FINANCIAL_INAPPLICABLE_CHECKS`：
`margin_improve` / `ar_gap` / `inventory_gap` / `construction` / `cash_debt`）。

**估值分 V**（机构口径，合计 100，`config.VALUATION_WEIGHTS`）：

```
机构目标价空间 40% + 预测 PE 相对当前 PE 20% + 预期未来净利增速 40%
```

**三块必须都有才给 V**：`has_valuation`（目标价或预测 PE 至少一个）与 `has_growth`
（预测增速）同时成立，且按**可用块的权重归一化**（`sum(score × max/100) / max_available × 100`）。
任一缺失 → V = `None`、`grade = 数据不足`，但 Q 照常展示。

**V 分档**（`score._valuation_score()`）：

| 下限 | 档名 |
|---:|---|
| 80 | 明显低估 |
| 65 | 低估 |
| 50 | 合理 |
| 35 | 偏高 |
| 0 | 明显高估 |

历史分位、FCF、现金底线**只展示，不进 V**。历史分位那套另有一个
`_historical_valuation()`：取可用分位的中位数，**≥2 个口径、≥52 周**才给分，
分位跨度超过阈值会额外说明——但它同样不写回 `v["score"]`，也不参与 `_decision()`。

**结论矩阵**（`DECISION_MATRIX`，V 门槛是"含"，从高到低取第一个满足的档）：Q 越低，要求的 V 越高；`Q < 45` 一律回避。

| Q 档 | V 门槛 → 结论（`label` 原文） |
|---|---|
| `Q ≥ 75` | V≥65 `推荐买入` ／ V≥50 `好公司，等价格` ／ V≥35 `好公司，但偏贵，等价格` ／ 其余 `好公司，但太贵` |
| `65 ≤ Q < 75` | V≥80 `推荐买入` ／ V≥70 `可买` ／ V≥50 `观察` ／ 其余 `回避` |
| `55 ≤ Q < 65` | V≥75 `小仓买入` ／ V≥50 `观察` ／ 其余 `回避` |
| `45 ≤ Q < 55` | V≥80 `小仓试错` ／ V≥65 `观察` ／ 其余 `回避` |
| `Q < 45` | 直接 `回避`（`质量分 xx 低于 45，禁止买入`） |

矩阵里**一共 9 个不同的 `label`**（推荐买入 / 好公司，等价格 / 好公司，但偏贵，等价格 /
好公司，但太贵 / 可买 / 观察 / 小仓买入 / 小仓试错 / 回避）。

矩阵之外还有 **3 种** `label`，它们不由 Q×V 决定：

| 结论 `label` | 什么时候出现 | 出处 |
|---|---|---|
| `数据不足，不下结论` | Q 或 V 算不出来（V 缺机构覆盖/目标价，或金融股不适用） | `_decision()` |
| `观察，等待数据完整` | 矩阵给了买入类，但数据前置条件不满足 | `_decision()` |
| `观察，第二节有信号` | 一致性闸门把买入类降级 | `_risk_gate()` |

9 + 3 = **12 种**。

另外两类结论**复用已有的 `label`**，只靠 `reason` / `note` 区分，所以不算新种类：

- **致命项** → `label="回避"`，`reason="出现致命风险：净资产为负"` 这样；
- **闸门的回避降级** → `label="回避"`，`note` 写"第二节：命中 N 项、提示 M 项 → 买入类结论降级为回避"。

**一致性闸门**（`score._gate_level()` / `_risk_gate()`）：Q 是连续打分，第二节是阈值判定，
同一科目可能在 Q 里扣分、又在第二节命中。结论取两者中更谨慎的一方：

```
hits ≥ 2  或  hits 里含 RISK_HEADLINE_KEYS（cash_flow / cash_debt）  → 买入类降为「回避」
watches ≥ 2  或  hits == 1                                          → 买入类降为「观察，第二节有信号」
```

**只在买入方向生效**：`result.key ∉ BUY_KEYS` 时直接 `return None`，不降级——太贵、
回避这些结论本来就更谨慎，再降一次没有意义，而且会把「数据不足」变成
「更保守等于更好」。

**可买的数据前置条件**（`_decision()` 里另外一条，与闸门独立）：机构覆盖 <3 家
（`BUY_MIN_INSTITUTION_COVERAGE`）、Q 数据覆盖 <80%（`BUY_MIN_QUALITY_COVERAGE`）、
或 `BUY_CRITICAL_CHECKS` 里任一项缺失（`cash_flow` / `leverage` / `goodwill` /
`nonrecurring` / `cash_debt`）时，**不给出可买**，降为「观察，等待数据完整」。
注意这五项是"关键检查"，比 14 项里的其余 9 项更硬。

## 项目结构

```
stock_quality_screen/
├── stock_report.py       CLI：参数、退出码、单股/批量编排
├── config.py             全部阈值、权重、决策矩阵（唯一一份）
├── screen/
│   ├── codes.py         股票代码号段规则（全项目唯一一份）
│   ├── fetch.py         取数层：全部走共享数据层
│   ├── compute.py       接口返回 → 计算用结构
│   ├── score.py         Q、V、14 条检查、致命项、闸门、决策矩阵、跟踪清单
│   ├── detail.py        五节报告的数据骨架（组装成 dict）
│   ├── render.py        五节报告 → HTML（渲染结果压进 payload.report_html）
│   ├── validate.py      轻量校验：只查计算链能否安全出结论
│   ├── batch.py         外部 CSV 读取（只读，只取代码与名称）
│   ├── fmt.py           数值格式化（全项目唯一一份）
│   └── util.py          安全数值与统计原语
└── tests/               helpers.py + 5 个 test_*.py
```

`score.py` 是唯一一处"算"，`detail.py` 只搬数据、`render.py` 只排版——
换展示不用动评分，换口径不用动模板。

`fmt.py` 只有一份是有原因的：以前每个模块各写一个 `_num()`，对 `nan` 的处理
各有不同，报告页面上出现过 `nan%`。现在统一入口 `_fmt()`，NaN / Inf 一律给 `—`。

**最容易漏、必须写死的几条**（都已落在测试里）：

1. 权重加起来必须是 100 —— 以前报告里那段说明是手写的，改权重后照旧印旧数字。
2. 决策矩阵的 V 区间必须由相邻 `v_min` 相减得来 —— 手抄一遍就会「说一套、算一套」。
3. `nan` / `inf` 必须给 `—`，不能漏成字符串 `"nan"`。
4. `clamp()` 对越界值是**截断到 `[0,100]`**（`test_util_fmt.py:184` 断言 `clamp(150) == 100`），
   `linear()` / `inverse()` 同样截断（`util.py:68-79` 的 docstring 写的就是"超出范围截断"）。
   ⚠️ 本文早先写的是"越界分位要跳过、不能夹取"，**代码里没有"跳过"这个分支**——
   所以"分位报 150 会不会被当成历史底部"这件事，实际结果是**会被夹成 100**。
   要改成跳过，得在 `num(percentile)` 之后加范围校验，属于改代码。
5. 金融股的货款占用要写「不适用」，不是「数据不足」—— 两者含义不同。
6. 「跳过」的退出码是 0，不是 2。
7. `920` 开头是北交所，必须排在 `9 → 上交所` 之前判断。
8. 续跑复用的行要把库里的 `payload` 原样带进新一次运行，否则最新一批只剩
   "这次真算的"几只，看板读最新 run 就少了一半票。复用行的 payload 是**旧形状**
   （键是 `q` / `v` / `conclusion`，不是 `q_score` / `v_score` / `label`），
   `_row_fields()` 两种都要认——只认一种的后果不是报错，而是把 Q/V 静默覆盖成空。

## 设计取舍

**门槛只有一份。** `config.py` 里的 `DECISION_MATRIX` 是唯一的门槛表，查表、测试、
看板的说明文字都从它来。0.9.8 之前查表和说明文字两处各写一遍，改一个门槛就变成
「说一套、算一套」。

**结论与展示解耦。** 这个工具只产出数据结构（Q/V/结论/理由/风险计数/完整 payload），
怎么画交给看板。所以「换一种展示」不再需要动评分代码，反之亦然。

**批量不重算分数。** 续跑时同一天已有的票直接从结果库复用，读到的是结论本身，
不再是 HTML 里抠出来的文本。

## 已知边界

- **金融股不套 FCF**：银行、保险、券商的经营现金流口径与制造业不可比，
  Q 的现金创造力维度标记为「不适用」，V 也不计算。
- **强周期股不套 FCF**：商品价格波动会让 FCF 大起大落，同理。
- **历史分位不进 V**：分位只作为参考展示。原因是一次性因素（重组、并表）会让
  历史区间失真，用它算分会把「历史便宜」误当成「现在便宜」。
- **垄断性不从财务数据反推**：资源 / 牌照型公司的毛利率随商品价格波动，σ 天然大，
  三条证据对它们结构性地判弱。报告里只显示人工标注（须带可核实来源）。
