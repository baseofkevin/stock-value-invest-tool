# 企业质量初筛工具

输入一个股票代码（或一份 CSV），输出一份**单文件 HTML 报告**：质量分 Q、估值分 V、
14 条风险检查、机构预期、跟踪清单，最后给一句结论。

只做**定量初筛**，不做行业研究、不给目标价、不写故事。结论只有九种，全部由
`config.DECISION_MATRIX` 一张表决定，报告里的「决策规则」说明文字也从同一张表生成
——说一套、算一套在这个项目里是设计错误，不是笔误。

数据来自共享数据层 `stock_data_fetch`（`../stock_data_fetch/`），本工具不直连任何上游。
零第三方依赖，只用 Python 标准库。

## 快速开始

```bash
cd stock_quality_screen

# 单只股票
python3 stock_report.py --stock-code 600519

# 批量（CSV 只读，不改动、不产出 CSV/Excel）
python3 stock_report.py --csv ../stock-kline-screen-tool/csv_output/选股_2026-10-14.csv

# 离线重放（不发网络请求）
python3 stock_report.py --stock-code 600519 --bundle tests/fixtures/mini_bundle.json
```

## CLI 参考

`--stock-code` 与 `--csv` 互斥且必填（二选一）。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--stock-code CODE` | — | `600519` / `sh600519` / `600519.SH` 都认 |
| `--csv FILE`（旧名 `--csv-input`） | — | 批量模式：读 CSV 的代码列（`代码` / `股票代码` / `证券代码` / `code`） |
| `--name NAME` | `""` | 覆盖报告文件名里的公司名，仅单股模式 |
| `--bundle PATH` | `""` | 离线采集包（旧 raw JSON），不发起网络请求 |
| `--timeout SEC` | `90` | 单次取数超时 |
| `--workers N` | `4` | 批量并发线程数 |
| `--retries N` | `2` | 取数失败后的重试次数 |
| `--retry-wait SEC` | `60` | 重试前等待秒数 |
| `--force` | 关 | 批量模式忽略已有报告，全部重生成 |
| `--quiet` | 关 | 只输出错误（连取数层的重试警告一起静音） |

**没有 `--out-dir`。** 输出目录由 `_out_dir_for()` 统一决定：

```
批量  output/quality-screen/<批次日期>/   ← 日期取自 CSV 文件名，其次「启动日」列，最后当天
单股  output/quality-screen/             ← 没有批次概念，不加日期层
```

以前 `--out-dir` 默认落在源码目录的 `html-report/`，又允许任意覆盖，于是同一个工具的
报告散在 `html-report/`、`html-report2/`、`/tmp/初筛` 好几处，「哪份最新」只能靠翻
mtime 猜。取消这个参数后产物位置是可预测的。

### 退出码

| 码 | 含义 |
|---|---|
| `0` | 成功（**含「跳过」**：上市不足 3 年不是错误） |
| `2` | 用户输入 / 数据问题（代码格式错、取数失败、校验不通过） |
| `3` | 未预期错误（该看堆栈了） |
| `130` | Ctrl-C 中断 |

「跳过」与「失败」必须分开：批量跑 155 只，混进 3 只次新股是常态，不该让整批返回非零。

```
└── 贵州茅台-企业质量初筛-20261014-101530.html   ← 单股模式直接落根下
```

单份报告是**单文件**：CSS 内联、图表是手写 SVG、无 JS、无外链字体。拷走就能看。

报告固定五节：

| 节 | 内容 |
|---|---|
| 一、生意本身 | 行业、主营、垄断性标注、存续安全、盈利结构（三条证据）、五年量化轨迹 |
| 二、经营质量与风险 | 14 条检查，分真伪 / 趋势 / 质量 / 安全四组；通过项折叠在每组末尾 |
| 三、企业估值与机构预期 | PE/PB/PS 历史分位与走势、机构预测、现金底线估值 |
| 四、综合评分 | Q、V、结论、两个分的构成、数据完整度、决策规则 |
| 五、后续跟踪 | 由评分和阈值自动生成的核对清单 |

## 评分口径

**质量分 Q**（五个维度，合计 100）：

| 维度 | 权重 |
|---|---|
| 资本回报 | 30 |
| 现金创造力 | 25 |
| 资产负债表 | 20 |
| 成长与稳定 | 15 |
| 会计质量 | 10 |

**估值分 V**（机构口径，合计 100）：

```
机构目标价空间 40% + 预测 PE 相对当前 PE 20% + 预期未来净利增速 40%
```

历史分位、FCF、现金底线**只展示，不进 V**。无机构覆盖时 V 不计算，但 Q 正常展示。

**结论矩阵**：Q 越低，要求的 V 越高；`Q < 45` 一律回避。

```
Q≥75：V≥65 推荐买入，50~65 等价格，35~50 偏贵，<35 太贵
Q65~75：V≥80 推荐买入，70~80 可买，50~70 观察，<50 回避
Q55~65：V≥75 小仓买入，50~75 观察，<50 回避
Q45~55：V≥80 小仓试错，65~80 观察，<65 回避
Q<45：回避，禁止买入；Q 或 V 缺失 → 数据不足
```

矩阵之外还有四种结论，它们不由 Q×V 决定：**数据不足**（Q/V 算不出来）、
**观察，等待数据完整**（矩阵给了买入类但数据前置条件不满足）、**回避**（致命项或
Q 低于硬下限）、**回避 / 观察**（一致性闸门触发）。

**一致性闸门**：Q 是连续打分，第二节是阈值判定，同一科目可能在 Q 里扣分、又在第二节
命中。结论取两者中更谨慎的一方 —— 命中 ≥2 项、或现金流质量 / 现金短债比命中 →
买入类降为回避；提示 ≥2 项、或命中 1 项 → 买入类降为「观察，第二节有信号」。
只在**买入方向**生效：太贵、回避这些结论本来就更谨慎，不再降一次，也避免
「数据缺失」被变成「更保守等于更好」。

**可买的数据前置条件**：机构覆盖 <3 家、Q 数据覆盖 <80%、关键风险检查缺失时，
不给出可买，降为「观察，等待数据完整」。

## 项目结构

```
stock_quality_screen/
├── stock_report.py       CLI：参数、退出码、单股/批量编排
├── config.py             全部阈值、权重、决策矩阵（唯一一份）
├── screen/
│   ├── codes.py         股票代码号段规则（全项目唯一一份）
│   ├── fetch.py         取数层：全部走共享数据层
│   ├── compute.py       接口返回 → 计算用结构
│   ├── score.py         Q、V、14 条检查、决策矩阵、跟踪清单
│   ├── validate.py      轻量校验：只查计算链能否安全渲染
│   ├── render.py        单文件 HTML 渲染（五节）
│   ├── index_html.py    批量导航页
│   ├── batch.py         CSV 读取与结果结构
│   ├── summary.py       从 HTML 里回读结论（批量模式的唯一数据源）
│   ├── fmt.py           数值格式化（全项目唯一一份）
│   └── util.py          安全数值与统计原语
├── templates/report.html
└── tests/
```

`fmt.py` 只有一份是有原因的：以前每个模块各写一个 `_num()`，对 `nan` 的处理
各有不同，报告页面上出现过 `nan%`。现在统一入口 `_fmt()`，NaN / Inf 一律给 `—`。

## 测试

```bash
python3 -m unittest discover -s tests -t .
```

**全程离线、零 mock 网络**：渲染与 CLI 测试用构造的 data，取数层不在测试范围内
（那是 `stock_data_fetch` 自己的测试该管的）。

| 文件 | 用例 | 覆盖 |
|---|---|---|
| `test_config_contract.py` | 46 | 权重合计 100、分档降序、矩阵首尾相接、已删常量不回流 |
| `test_util_fmt.py` | 64 | 数值收敛、样本标准差 n−1、`cagr` 返回百分数、`nan`/`inf` → `—` |
| `test_score.py` | 58 | 质量分方向性、致命项、矩阵逐格可达、闸门与数据前置条件 |
| `test_render.py` | 56 | 报告结构、`data-metric` 锚点、配色门槛来自 config、降级路径、summary 回退 |
| `test_cli.py` | 54 | 参数互斥、已删参数拒绝、输出目录推导、退出码映射 |
| `test_codes.py` | 31 | 号段归属（920/4/8 → 北交所）、显式前缀优先、两套输出格式 |

**最容易漏、必须写死的几条**（都已落在测试里）：

1. `data-metric="q|v|conclusion"` 三个锚点一个不少 —— 少一个，批量导航页整列变
   「评分提取失败」，而且**不报错**。
2. 权重说明里印出来的数字加起来必须是 100 —— 以前这段是手写的，改权重后报告照旧
   印旧数字。
3. 决策矩阵的 V 区间必须由相邻 `v_min` 相减得来 —— 手抄一遍就会「说一套、算一套」。
4. `nan` / `inf` 必须给 `—`，不能漏成字符串 `"nan"`。
5. 越界分位（`-5` / `150`）要**跳过**，不能夹取成「历史底部」—— 夹取比跳过更误导。
6. 金融股的货款占用要写「不适用」，不是「数据不足」—— 两者含义不同。
7. 「跳过」的退出码是 0，不是 2。
8. `920` 开头是北交所，必须排在 `9 → 上交所` 之前判断。
9. 北交所的东财 URL 是 `/bj/920001.html`，不是 `bj920001.html`（后者 404）。
10. `summary` 命中任一标记位就**不再回退**老格式：混读会给出半对半错的结论，
    报错让人去看那份报告，更安全。

## 设计取舍

**门槛只有一份。** `config.py` 里的 `DECISION_MATRIX` 同时供 `score._decision()` 查表
和 `render._matrix_text()` 生成说明文字。0.9.8 之前这两处各写一遍，改一个门槛就变成
「说一套、算一套」，旧说明里 Q≥75 那档写的是「50~65 等价格」，代码其实是 50~65 之外
还有 35~50，两边对不上。

**权重也由 config 拼出来。** 报告里的「质量分 Q：资本回报 30、…」是
`_weight_text(config.QUALITY_WEIGHTS, ...)` 生成的，不是手抄的。

**渲染层不重算数字。** 它只读 `compute_scores()` 的输出，`None` 就印 `—`。
算错了是 score 的测试该抓的，渲染层不该有第二套口径。

**批量不重算分数。** 导航页里的结论从已落盘的 HTML 里解析（`summary.py`），
用户点开报告看到什么，导航页就写什么。

**输出目录不带参数。** 见 [CLI 参考](#cli-参考)。

## 已知边界

- **金融股不套 FCF**：银行、保险、券商的经营现金流口径与制造业不可比，
  Q 的现金创造力维度标记为「不适用」，V 也不计算。
- **强周期股不套 FCF**：商品价格波动会让 FCF 大起大落，同理。
- **历史分位不进 V**：分位只作为参考展示。原因是一次性因素（重组、并表）会让
  历史区间失真，用它算分会把「历史便宜」误当成「现在便宜」。
- **垄断性不从财务数据反推**：资源 / 牌照型公司的毛利率随商品价格波动，σ 天然大，
  三条证据对它们结构性地判弱。报告里只显示人工标注（须带可核实来源）。
